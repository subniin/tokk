Build your own in four steps.

Use this templateStart a repository from Tokk on GitHub.
Teach your soundsRecord each sound 10 times on the teach page, or let users teach their own.
Map patterns to actionsA TypeScript object: pattern on the left, function on the right.
Test with a recordingRun a WAV through the same engine in Node and check the patterns.
import { listen } from 'tokk';

const ears = await listen({
  storageKey: 'tokk:slides',
  on: {
    'clap clap': () => deck.next(),
    'clap clap clap': () => deck.prev(),
  },
});
// first run: the user teaches their own clap
if (!ears.labels.includes('clap')) await ears.teach('clap', { ui: true });

How it works

MicrophoneOpened after a click, on HTTPS.
AudioWorkletCopies 20 ms chunks, nothing else.audio thread
WorkerRuns the engine off the main thread.worker
SegmentsFinds where a sound starts and ends.
FeaturesTurns each sound into 32 numbers.
Nearest soundsNames it, or says unknown.
PatternsCalls your function.main thread

A pattern waits while a longer one can still match, then fires at once.

Built with Kiro.

SpecsEvery part of Tokk and both apps started as a Kiro spec: requirements, design, tasks, tests first..kiro/specs/
SteeringRules Kiro follows everywhere, like "audio never leaves the device".
HooksProperty tests and a public-API check run on save.
AgentsAn integrator agent wires Tokk into an app and writes its tests.
PowerMCP tools that let Kiro listen to a WAV, score it and see a spectrogram.How Kiro was used

Audio stays on the device. Tokk keeps feature vectors, not recordings, and sends nothing to a server.
